# Tier 2 & Tier 3 半自动化提交流程 (Semi-Automated Playbook)

对于 ProductHunt、HackerNews、Futurepedia 等必须强账号绑定、甚至有人工审核机制的高价值平台，我们**不适用完全无头的后台盲打**，但是**非常适合采用“半自动化 (Semi-Automated)”助手模式**。

这种模式下，代码不是您的替代品，而是您的外骨骼装甲。

## 1. 半自动化方案的核心思路

相比由于卡在验证码和登录态而频繁失败的全自动脚本，半自动化方案将“机器擅长的事”和“人必须做的事”完美解耦：

### 🤖 机器（Playwright）负责：
- **启动物理指纹正常的浏览器实例**（非 Headless 模式，界面可见）。
- **通过 Cookie Session 注入**直接跳过扫码登录环节（或者停留在对应页面等您登录）。
- **一键读取本地 `product-meta.json`**。
- **神速且精准地自动填入**所有枯燥的表单项（产品名、几十种变体 Slogan、官网链接、社交媒体、融资轮次、标签枚举等）。
- **自动上传**本地配置好的 Logo 和截图附件。

### 🧑‍💻 人类（您）负责：
- 喝着咖啡看着浏览器自己把表格瞬间填满。
- **手工解决**（点击）一下页面上的 Google reCaptcha 或 Cloudflare 盾牌。
- 如果需要，针对 ProductHunt 等社区**手工微调**一下“Maker 的首发致辞”使之更具人情味。
- **点击最终的 Submit 按钮**。

---

## 2. 为什么这种模式对于 ProductHunt 最优？

1. **绝对安全，防止封号**：高价值平台的风控极其严格（甚至追踪鼠标轨迹和键盘敲击事件）。Playwright 在非无头模式下通过人类点击最后一步，能够完美且安全地通过所有反作弊检测。
2. **账号权重保留**：这些平台提交内容的展现量往往与提交者（Hunter/Maker）的账号历史权重挂钩。半自动化允许您复用日常使用的高权重账号登录态进行发布。
3. **极大地节省心智**：填写一个 ProductHunt 或 AlternativeTo 标准档案往往需要 10-15 分钟（不断复制粘贴各类链接和文案）。半自动脚本只需 **3 秒钟** 即可把草稿填完，您只需要做最后的 Review。

## 3. 下一步实现计划 (如果需要开发)

如果您认为这种模式适合，我们可以在现有的工程中：
1. 在 `auto-submitter` 目录下开辟一个新的 npm 脚本：`npm run submit:manual`。
2. 利用现有的 `GenericFormAdapter` 逻辑，稍加修改：
   - 移除 `headless: true`，展示 Chromium 界面。
   - 增加一个 `await page.pause()` 的断点指令。
3. 帮您开发一个简单的指引，告诉您如何将 Chrome 的用户数据目录 (User Data Dir) 映射过来，使得脚本打开浏览器时您就**已经是登录状态**。

您觉得这个思路如何？如果您准备好了，我们可以马上动手把半自动化辅助填表的功能集成进去！
