## MCP 인증은 연결 성공보다 권한 경계가 더 중요하다

MCP 서버를 붙일 때 많은 팀이 먼저 "연결되느냐"를 확인합니다. 하지만 운영 단계에서 더 중요한 것은 누가 어떤 도구를 어떤 범위까지 호출할 수 있는지입니다. 인증이 약하면 편리해 보여도, 결국 도구 오용과 과도한 권한 부여 때문에 더 큰 운영 비용을 치르게 됩니다.

## 인증 방식을 고를 때 보는 기준

인증 수단은 하나만 정답인 경우가 드뭅니다. 서버 성격과 사용자 범위에 따라 선택해야 합니다.

- **API 키**: 서버 간 통신이나 내부 자동화에 단순하게 적용하기 좋음
- **세션 토큰**: 짧은 수명의 권한 위임에 유리함
- **OAuth**: 사용자별 권한 위임과 외부 서비스 연동에 적합함
- **사내 SSO 연동**: 조직 단위 접근 제어와 감사 요구가 있을 때 유리함

핵심은 인증 수단 자체보다, 그 수단이 실제 권한 모델과 맞아떨어지는지입니다.

## 도입 전 확인 사항

MCP 인증을 설계하기 전에 아래 질문부터 정리하는 것이 좋습니다.

### 누가 서버를 호출하는가

사용자 개인이 직접 호출하는지, 데스크톱 앱이 대신 호출하는지, 백엔드 서비스가 중간에서 대행하는지에 따라 적합한 인증 방식이 달라집니다.

### 어떤 도구가 더 민감한가

문서 검색과 파일 삭제 도구를 같은 권한으로 열어 두면 안 됩니다. 도구별로 민감도를 나누고, 최소 권한 원칙을 적용해야 합니다.

### 인증 실패 시 어떻게 대응할 것인가

만료된 토큰, 누락된 헤더, 범위를 벗어난 권한 요청이 들어왔을 때 어떤 메시지를 반환할지 미리 정해 두어야 클라이언트 디버깅이 쉬워집니다.

## 안전한 설정을 위한 보안 통제

### 최소 권한 원칙

인증이 통과했다고 해서 모든 도구를 열어 주면 안 됩니다. 읽기 전용 도구와 변경 가능한 도구를 분리하고, 사용자나 클라이언트 종류별로 허용 범위를 나누는 것이 기본입니다.

### 짧은 수명의 자격 증명

장기 API 키를 오래 유지할수록 유출 시 피해가 커집니다. 가능하면 수명이 짧은 토큰과 주기적 회전 정책을 사용해야 합니다.

### 서버 측 검증

클라이언트가 "이 사용자는 관리자입니다"라고 주장하도록 두지 말고, 서버가 직접 토큰과 scope를 해석해야 합니다. 권한 판단 기준은 항상 서버에 있어야 합니다.

### 감사 로그

누가 어떤 도구를 호출했고, 거부된 요청은 무엇이었는지 남겨야 합니다. 보안 사고 대응뿐 아니라 정상적인 운영 문제를 분석할 때도 큰 도움이 됩니다.

## API 키를 쓸 때 흔한 실수

간단해서 많이 쓰이지만, API 키는 관리가 느슨해지기 쉽습니다.

- 코드나 설정 파일에 키를 직접 하드코딩함
- 개발용 키와 운영용 키를 분리하지 않음
- 키별 사용 주체를 구분하지 않음
- 회전 주기 없이 장기간 동일 키를 사용함

이런 상태에서는 "인증이 있다"고 보기 어렵습니다. 최소한 발급 주체, 사용 범위, 만료 정책은 함께 관리해야 합니다.

## OAuth가 필요한 시점

사용자별 권한 위임이 필요하거나, Google Drive·GitHub·Slack 같은 외부 SaaS에 연결하는 도구를 제공한다면 OAuth가 더 자연스럽습니다. 이 경우 중요한 것은 로그인 자체가 아니라, 어떤 범위의 액세스를 요청하고 어떻게 갱신 토큰을 보관하느냐입니다.

특히 다수의 외부 서비스와 연결될수록 동의 화면의 설명과 scope 축소 전략이 중요해집니다.

## 운영 단계에서 점검할 항목

인증은 붙이는 순간보다 운영하면서 더 자주 점검해야 합니다.

- 토큰 만료와 갱신 실패율
- 도구별 권한 거부 빈도
- 비정상적인 호출 패턴과 rate limit 초과
- 퇴사자·비활성 계정의 접근 차단 여부

이 지표를 꾸준히 보면, 보안 문제를 큰 사고 전에 발견할 수 있습니다.

## 결론

MCP 인증은 단순한 로그인 절차가 아니라 도구 사용 경계를 정의하는 설계 문제입니다. API 키든 OAuth든 중요한 것은 각 도구의 민감도와 사용자 역할에 맞게 권한을 세분화하는 것입니다.

처음부터 복잡한 체계를 만들 필요는 없지만, 최소 권한·짧은 수명·서버 측 검증·감사 로그 네 가지는 반드시 갖추는 편이 좋습니다. 이 기본기가 있어야 MCP 서버를 안전하게 확장할 수 있습니다.
