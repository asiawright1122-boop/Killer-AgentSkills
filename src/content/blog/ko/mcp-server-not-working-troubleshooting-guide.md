## MCP 서버가 안 될 때는 증상보다 경로를 먼저 나눠야 한다

MCP 서버 문제는 겉으로 보면 비슷합니다. 연결이 안 되거나, 도구 목록이 비어 있거나, 호출은 되는데 응답이 이상합니다. 하지만 원인은 전혀 다른 층에 있을 수 있습니다. 그래서 가장 먼저 해야 할 일은 "무엇이 안 되나"를 묻는 것이 아니라, 어느 구간에서 멈췄는지 경로를 나누는 것입니다.

## 문제 분류와 진단 순서

실전에서는 아래 순서로 확인하면 시간을 가장 많이 아낄 수 있습니다.

1. **프로세스가 실제로 떠 있는지 확인**
2. **클라이언트가 서버까지 연결되는지 확인**
3. **초기 핸드셰이크와 도구 목록 노출이 정상인지 확인**
4. **개별 도구 호출 시 입력과 응답 포맷이 맞는지 확인**
5. **인증·권한·외부 API 의존성 문제를 분리해서 확인**

이 순서를 건너뛰면, 포맷 오류를 네트워크 문제로 착각하거나 인증 실패를 서버 다운으로 오해하기 쉽습니다.

## 가장 먼저 볼 네 가지 증상

### 서버가 아예 시작되지 않는다

이 경우는 대개 런타임 버전, 환경 변수 누락, 필수 패키지 설치 실패, 시작 명령 오타에서 시작됩니다. 최근에 설정 파일을 바꿨다면 그 변경부터 의심하는 편이 빠릅니다.

### 서버는 시작되지만 클라이언트가 연결하지 못한다

포트, 전송 방식, 실행 경로, 접근 가능한 호스트 설정을 확인해야 합니다. 로컬에서는 되는데 특정 에디터나 에이전트에서만 실패한다면 클라이언트 쪽 설정 불일치일 가능성이 큽니다.

### 도구 목록이 보이지 않는다

초기화는 되었지만 서버가 도구를 제대로 등록하지 못했을 수 있습니다. 서버 코드의 등록 로직, 조건부 로딩, 권한별 노출 정책을 살펴보는 것이 좋습니다.

### 도구 호출은 되지만 결과가 이상하다

이 단계에서는 MCP 연결 자체보다 입력 스키마, 직렬화, 외부 서비스 응답 처리, 타임아웃 설정을 점검해야 합니다.

## 원인별로 나눠 보는 점검 포인트

### 설정 문제

가장 흔한 원인입니다. 서버 실행 경로가 틀리거나, 필요한 secret이 빠졌거나, 개발 환경과 운영 환경의 변수 이름이 다른 경우가 많습니다. 특히 JSON 설정 파일을 손으로 관리하면 작은 오타가 전체 실패로 이어집니다.

### 인증 문제

연결은 되지만 특정 도구만 실패한다면 인증 scope가 부족할 수 있습니다. 만료된 토큰이나 잘못된 헤더 형식도 자주 보이는 원인입니다.

### 외부 의존성 문제

MCP 서버가 내부적으로 데이터베이스, SaaS API, 파일 시스템을 호출한다면 실제 실패 지점은 서버 바깥일 수 있습니다. 이때는 서버 로그만으로 결론 내리지 말고, 외부 호출 성공 여부를 따로 분리해 확인해야 합니다.

### 응답 포맷 문제

에이전트가 기대하는 구조와 실제 반환 구조가 다르면, 사용자 입장에서는 "아무 반응이 없음"처럼 보일 수 있습니다. JSON 직렬화 오류나 필드 누락이 특히 흔합니다.

## 로그를 볼 때 놓치기 쉬운 부분

문제 해결이 오래 걸리는 팀은 로그를 많이 남기지만, 필요한 맥락이 빠져 있는 경우가 많습니다. 아래 정보가 함께 남아야 진단이 쉬워집니다.

- 어떤 도구가 호출되었는지
- 어떤 입력 스키마가 들어왔는지
- 인증 주체가 누구인지
- 외부 API 호출 전후 상태가 어땠는지
- 실패가 초기화 단계인지 실행 단계인지

에러 문장 한 줄만 남아 있으면 원인 추적이 거의 불가능합니다.

## 재현 가능한 진단 루틴 만들기

운영 중인 서버라면 문제를 사람 감각에만 맡기지 말고, 반복 가능한 체크리스트를 두는 편이 좋습니다.

- 서버 기동 확인
- 도구 목록 조회 확인
- 대표 도구 1~2개의 샘플 호출 확인
- 인증이 필요한 도구와 필요 없는 도구를 분리해 확인
- 외부 API 장애 시 대체 응답이나 에러 메시지 확인

이 루틴이 있으면 장애가 났을 때 "무엇부터 볼지"를 두고 헤매는 시간이 줄어듭니다.

## 자주 하는 오해

MCP 서버 문제라고 해서 항상 MCP 프로토콜 자체가 원인은 아닙니다. 실제로는 설정 누락, 비밀 정보 만료, 외부 API 제한, 응답 스키마 변경처럼 주변 요소 때문에 발생하는 경우가 더 많습니다.

그래서 문제를 좁힐 때는 "MCP가 이상하다"고 넓게 보지 말고, 실행 경로·연결·초기화·도구 실행·외부 의존성 순서로 잘게 쪼개는 편이 훨씬 효과적입니다.

## 결론

MCP 서버가 작동하지 않을 때 가장 중요한 것은 증상을 빠르게 분류하고, 실패 지점을 한 단계씩 좁혀 가는 것입니다. 시작 실패, 연결 실패, 도구 노출 실패, 실행 실패는 각각 보는 포인트가 다릅니다.

한 번의 장애를 해결하는 데서 끝내지 말고, 로그 항목과 진단 순서를 정리해 두면 다음 문제는 훨씬 빨리 해결할 수 있습니다. 결국 좋은 문제 해결 가이드는 정답 목록이 아니라, 원인을 빠르게 분리하는 기준을 제공하는 문서입니다.
