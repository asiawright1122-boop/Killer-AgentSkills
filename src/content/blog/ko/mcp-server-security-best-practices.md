## MCP 서버 보안은 도구 기능보다 통제 지점 설계가 핵심이다

MCP 서버는 모델이 외부 시스템을 만나는 접점입니다. 그래서 일반 웹 API와 비슷한 보안 원칙이 필요하면서도, 도구 호출이라는 특성 때문에 더 세밀한 통제가 필요합니다. 무엇을 열어 줄지보다, 어떤 경계 안에서 열어 줄지를 먼저 설계해야 합니다.

## 프로덕션 배포 전에 반드시 정리할 것

보안을 강화하려면 기능 출시 직전에 체크리스트만 붙여서는 부족합니다. 아래 항목은 설계 초기에 정리하는 편이 좋습니다.

- 어떤 도구가 읽기 전용인지, 어떤 도구가 변경 권한을 가지는지
- 사용자·클라이언트·서비스 계정별 접근 범위가 어떻게 다른지
- 감사가 필요한 작업과 단순 조회 작업을 어떻게 구분할지
- 장애 시 차단 우선인지, 제한적 허용 우선인지

이 기준이 없으면 인증을 붙여도 실제 권한 통제는 느슨해지기 쉽습니다.

## 보안 통제의 기본 축

### 입력 검증

모델이 생성한 입력은 사람이 직접 작성한 요청보다 예측이 어렵습니다. 경로, 쿼리, 명령 인자, 문서 ID 같은 값은 모두 서버에서 다시 검증해야 합니다. 허용 가능한 형식을 명시하고, 예상 범위를 벗어난 값은 일찍 거부하는 편이 안전합니다.

### 권한 분리

모든 호출 주체에게 동일한 권한을 주면 운영이 편해 보여도 사고 확률이 급격히 올라갑니다. 읽기, 쓰기, 삭제, 배포, 관리자 기능은 최소한 별도 권한으로 나누는 것이 좋습니다.

### 속도 제한과 사용량 제어

MCP 서버는 자동화된 에이전트가 짧은 시간 안에 반복 호출할 수 있습니다. rate limit과 동시 실행 제한이 없으면 정상 사용도 쉽게 장애로 번집니다. 비용이 큰 도구일수록 별도 한도를 두는 편이 좋습니다.

### 감사 로그

보안 사고 대응에서 가장 늦게 후회하는 부분이 로그입니다. 누가, 언제, 어떤 도구를, 어떤 결과로 호출했는지 남겨야 합니다. 특히 거부된 요청과 관리자 수준 작업은 별도로 추적할 수 있어야 합니다.

## 네트워크와 실행 환경 보안

도구 코드가 안전해도 배포 환경이 느슨하면 전체 시스템은 취약해집니다.

- 외부 공개가 필요 없는 서버는 사설 네트워크나 게이트웨이 뒤에 둔다
- 비밀 정보는 런타임 secret 관리 기능으로 주입한다
- 운영 환경과 개발 환경의 자격 증명을 분리한다
- 아웃바운드 네트워크 접근도 필요한 대상만 허용한다

특히 사내 시스템과 연결된 MCP 서버는 "접속만 되면 무엇이든 가능"한 구조를 피해야 합니다.

## 모델 특성 때문에 더 주의할 점

MCP 서버는 일반 API와 달리, 상위 모델이 어떤 도구를 언제 선택할지에 영향을 받습니다. 그래서 보안 설계에서 다음을 추가로 고려해야 합니다.

### 과도한 도구 권한 노출

모델이 사용할 수 있는 도구가 많을수록 예상 밖 조합이 생길 수 있습니다. 실제 사용 목적과 무관한 민감 도구는 기본 비활성화 상태로 두는 편이 낫습니다.

### 프롬프트 기반 오용 가능성

악의적인 입력이 도구 사용을 유도할 수 있으므로, 서버는 요청 의도를 신뢰하지 말고 항상 정책 기준으로 판단해야 합니다.

### 설명 가능한 거부 응답

정책상 차단된 요청은 왜 거부되었는지 명확히 남겨야 합니다. 그래야 개발자가 우회 설정을 만들지 않고, 정상적인 권한 조정 절차를 따르게 됩니다.

## 운영 중 점검해야 할 지표

보안은 배포 후에도 계속 관찰해야 합니다. 다음 지표를 보면 위험 신호를 빨리 잡을 수 있습니다.

- 비정상적으로 많은 도구 호출 빈도
- 특정 사용자나 토큰에 집중된 실패율
- 평소와 다른 시간대의 관리자 작업
- 갑작스러운 대량 조회·대량 수정 패턴
- 새로 추가된 도구의 사용량 급증

숫자 자체보다 평소 패턴에서 얼마나 벗어났는지를 보는 것이 중요합니다.

## 규정 준수와 내부 통제

금융, 의료, 엔터프라이즈 환경처럼 규정 준수 요구가 있는 경우에는 단순 보안 설정만으로는 부족합니다. 데이터 보관 기간, 접근 승인 절차, 민감 정보 마스킹, 로그 보존 정책까지 함께 정리해야 합니다.

이때 MCP 서버는 단순한 개발 도구가 아니라 실제 업무 시스템의 일부로 취급해야 합니다.

## 결론

프로덕션용 MCP 서버 보안은 인증 하나로 끝나는 문제가 아닙니다. 입력 검증, 권한 분리, 사용량 제어, 감사 로그, 네트워크 제한이 함께 맞물려야 안정적인 통제가 가능합니다.

가장 실용적인 접근은 처음부터 완벽한 보안 체계를 만들려 하기보다, 민감한 도구부터 강하게 잠그고 로그와 권한 모델을 먼저 정교하게 다듬는 것입니다. 그렇게 해야 서버를 확장해도 보안 수준이 무너지지 않습니다.
