## MCP와 REST API는 서로를 대체하기보다 쓰임새가 다르다

MCP와 REST API를 비교할 때 흔히 "새로운 프로토콜이 기존 API를 대신하느냐"는 식으로 접근합니다. 하지만 실무에서는 둘이 경쟁하기보다 서로 다른 역할을 맡는 경우가 많습니다. REST API는 범용 시스템 통합에 강하고, MCP는 모델과 도구 사이의 상호작용을 더 다루기 쉬운 형태로 정리하는 데 강합니다.

## 비교 기준을 분명히 해야 한다

어떤 방식을 고를지는 아래 기준에 따라 달라집니다.

- 호출 주체가 일반 애플리케이션인지, AI 에이전트인지
- 도구 설명과 입력 스키마를 모델 친화적으로 노출해야 하는지
- 여러 클라이언트가 같은 기능을 재사용해야 하는지
- 권한 통제와 감사 지점을 어디에 둘 것인지
- 기존 시스템과의 호환성이 얼마나 중요한지

이 기준 없이 단순 성능이나 유행만 보고 선택하면, 나중에 아키텍처가 어색해집니다.

## REST API가 여전히 강한 영역

REST API는 대부분의 백엔드 시스템에서 이미 검증된 방식입니다. 리소스 중심 설계, 명확한 엔드포인트, 표준적인 인증과 캐싱 전략이 잘 맞는 환경에서는 지금도 가장 실용적입니다.

다음과 같은 경우에는 REST가 자연스럽습니다.

- 모바일 앱, 웹앱, 백오피스 등 여러 일반 클라이언트가 함께 사용해야 할 때
- 리소스 CRUD와 명확한 비즈니스 엔드포인트가 중심일 때
- 기존 인프라와 관측 체계가 REST를 전제로 구축돼 있을 때
- 공개 개발자 API를 제공해야 할 때

즉, 일반 소프트웨어 간 통신이라면 REST는 여전히 기본 선택지입니다.

## MCP가 더 적합한 영역

MCP는 모델이 사용할 도구를 구조적으로 설명하고, 호출 가능한 기능을 일관된 방식으로 노출하는 데 강합니다. 에이전트가 파일 읽기, 검색, 문서 조회, 외부 서비스 호출 같은 도구를 선택적으로 사용할 때 특히 유용합니다.

다음 상황에서 장점이 큽니다.

- AI 에이전트가 어떤 도구를 쓸지 동적으로 선택해야 할 때
- 도구 메타데이터와 입력 스키마를 표준화해 재사용하고 싶을 때
- 여러 AI 클라이언트가 같은 도구 서버를 공유해야 할 때
- 툴 사용 권한을 서버 단에서 통제하고 싶을 때

## 도입 전 확인 사항

### 기존 시스템을 그대로 노출할 것인가

이미 잘 운영되는 REST API가 있다면, 이를 바로 폐기할 이유는 없습니다. 오히려 REST API는 유지한 채, AI 에이전트가 다루기 편한 형태로 MCP 계층을 얹는 방식이 현실적입니다.

### 호출 단위가 리소스 중심인지 작업 중심인지

리소스 상태를 조회하고 변경하는 작업이 대부분이면 REST가 명확합니다. 반면 검색, 요약, 생성, 분석, 파일 조작처럼 "도구 실행" 성격이 강하면 MCP가 더 자연스럽게 느껴질 수 있습니다.

### 누구를 위한 인터페이스인가

사람이 설계한 클라이언트가 쓰는 인터페이스인지, 모델이 해석하고 선택해야 하는 인터페이스인지에 따라 설계 기준이 크게 달라집니다.

## 함께 쓰는 구조가 가장 현실적일 때

많은 팀은 결국 둘 중 하나만 고르지 않습니다. 가장 실용적인 구조는 다음과 같습니다.

- **기존 비즈니스 시스템**은 REST API로 유지
- **AI 에이전트용 도구 계층**은 MCP로 제공
- **권한·감사·정책 통제**는 MCP 서버에서 한 번 더 관리

이렇게 하면 기존 시스템을 무리하게 바꾸지 않으면서도, 에이전트 친화적인 인터페이스를 별도로 설계할 수 있습니다.

## 선택을 단순하게 정리하면

- 범용 시스템 통합이 목적이면 **REST API**가 더 적합합니다.
- AI 에이전트가 도구를 선택하고 호출하는 경험이 핵심이면 **MCP**가 더 적합합니다.
- 이미 REST 자산이 많다면 **REST를 유지하고 MCP를 앞단에 두는 혼합 방식**이 현실적입니다.

## 결론

MCP와 REST API는 어느 하나가 다른 하나를 완전히 대체하는 관계가 아닙니다. REST는 범용 애플리케이션 통합의 표준으로 강하고, MCP는 모델이 외부 도구를 다루는 경험을 정리하는 데 강합니다.

중요한 것은 기술 이름보다 인터페이스의 소비자가 누구인지입니다. 사람이 설계한 앱을 위한 인터페이스라면 REST가, 모델이 이해하고 선택해야 하는 도구 계층이라면 MCP가 더 자연스럽습니다. 이 차이를 기준으로 보면 선택이 훨씬 쉬워집니다.
