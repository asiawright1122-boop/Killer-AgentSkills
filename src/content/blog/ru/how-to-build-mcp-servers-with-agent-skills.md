# Как создавать серверы MCP, которыми ИИ-агенты действительно пользуются

Что, если бы ваш ИИ-агент для кодинга умел не только писать код? Что, если бы он мог отправлять сообщения в Slack, запрашивать базы данных, выкатывать изменения в продакшен и управлять целым DevOps-конвейером — и всё это через стандартизированный протокол?

Именно это и делают возможным **серверы MCP** (Model Context Protocol). А с официальным навыком **mcp-builder** из репозитория навыков Anthropic вы можете собрать сервер MCP продакшен-уровня за минуты, а не за часы.

```bash
# Установите навык mcp-builder одной командой
npx killer-skills add anthropics/skills/mcp-builder
```

Хороший сервер MCP начинается не с длинного чеклиста, а с решения о том, какие возможности действительно стоит вынести в инструменты, как описать их для агента и какие эксплуатационные границы задать заранее.

## Что такое сервер MCP?

Сервер **MCP** — это стандартизированная служба, которая предоставляет инструменты, ресурсы и подсказки для использования агентами ИИ. Представьте его как мост между вашим ИИ-помощником и реальным миром — базами данных, API, файловыми системами, облачными сервисами и многим другим.

**Протокол контекста модели** (MCP) был создан Anthropic для решения фундаментальной проблемы: агентам ИИ нужен универсальный способ взаимодействовать с внешними сервисами. До MCP каждая интеграция требовала отдельного кастомного кода. Теперь всё это может обслуживать один протокол.

Вот почему MCP важен:

- **Универсальная совместимость** — работает с Claude, Cursor, Windsurf и любым клиентом, совместимым с MCP
- **Стандартизированный интерфейс** — инструменты, ресурсы и подсказки следуют единой схеме
- **Безопасность по умолчанию** — встроенная аутентификация, проверка ввода и контроль разрешений
- **Комбинируемые рабочие процессы** — агенты могут связывать несколько инструментов MCP в одну цепочку

## Почему стоит использовать навык mcp-builder?

Навык **mcp-builder** — один из самых мощных в официальном репозитории Anthropic. Он превращает Claude в специализированного разработчика серверов MCP и даёт вам следующее:

1. **Глубокое знание протокола** — навык загружает полную спецификацию MCP, чтобы Claude понимал все детали
2. **Встроенные лучшие практики** — именование инструментов, обработка ошибок и шаблоны пагинации уже продуманы заранее
3. **Руководства под конкретные фреймворки** — оптимизированные шаблоны для TypeScript и Python
4. **Генерация оценок** — автоматическое создание тестовых наборов для вашего сервера MCP

Вместо хаотичной сборки с нуля навык mcp-builder ведёт по структурированному четырёхфазному процессу:

| Фаза | Что происходит |
|:------|:-------------|
| **Фаза 1: Исследование** | Изучает API, планирует покрытие инструментов и проектирует схему |
| **Фаза 2: Сборка** | Реализует сервер с корректной обработкой ошибок и аутентификацией |
| **Фаза 3: Проверка** | Тестирует все инструменты, проверяет ответы и граничные случаи |
| **Фаза 4: Оценка** | Создаёт автоматизированные оценки для подтверждения качества |

## С чего начать на практике

### Установить навык

Глобальная установка CLI не нужна. Просто добавьте навык mcp-builder напрямую через `npx`:

```bash
npx killer-skills add anthropics/skills/mcp-builder
```

Навык будет добавлен в каталог `.claude/skills/` и автоматически активирован, когда Claude обнаружит задачу по разработке сервера MCP.

### Выбрать стек

Навык mcp-builder поддерживает два основных стека:

**TypeScript (рекомендуется)**
```bash
npm init -y
npm install @modelcontextprotocol/sdk zod
```

TypeScript рекомендуют по нескольким причинам:
- качественная поддержка SDK от официальной команды MCP
- статическая типизация обнаруживает ошибки до выполнения
- высокая совместимость со средами исполнения
- ИИ-модели хорошо генерируют код на TypeScript

**Python**
```bash
pip install mcp pydantic
```

Python — отличный выбор, если ваша команда уже на нём работает или если вы интегрируетесь с API, сильно завязанными на Python.

### Определить инструменты

Ключ к отличному серверу MCP — хорошо спроектированные инструменты. Вот простой шаблон:

```typescript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { z } from "zod";

const server = new McpServer({
  name: "my-api-server",
  version: "1.0.0",
});

server.tool(
  "create_item",
  "Создаёт новый элемент в системе",
  {
    name: z.string().describe("Имя элемента для создания"),
    description: z.string().optional().describe("Необязательное описание"),
    tags: z.array(z.string()).optional().describe("Теги для категоризации"),
  },
  async ({ name, description, tags }) => {
    const result = await api.createItem({ name, description, tags });
    return {
      content: [
        {
          type: "text",
          text: JSON.stringify(result, null, 2),
        },
      ],
    };
  }
);
```

### Применить важные практики

Навык mcp-builder закрепляет несколько критически важных паттернов:

**Схема именования инструментов**
```
github_create_issue
slack_send_message
db_query_users

createIssue
send
doStuff
```

Используйте последовательные префиксы (имя сервиса) и глаголы, ориентированные на действие. Это помогает агентам быстро находить и выбирать правильные инструменты.

**Понятные сообщения об ошибках**
```typescript
// ❌ Плохо
throw new Error("Не найдено");

// ✅ Хорошо
throw new Error(
  `Репозиторий "${owner}/${repo}" не найден. ` +
  `Проверьте, что репозиторий существует и у вас есть доступ. ` +
  `Попробуйте сначала вывести список репозиториев через github_list_repos.`
);
```

**Аннотации инструментов**

Каждый инструмент должен включать аннотации, которые помогают агентам понять его поведение:

```typescript
server.tool(
  "delete_item",
  "Постоянно удаляет элемент",
  { id: z.string() },
  async ({ id }) => { /* ... */ },
  {
    annotations: {
      readOnlyHint: false,
      destructiveHint: true,
      idempotentHint: true,
    }
  }
);
```

## Реальный пример: строим GitHub MCP-сервер

Рассмотрим реалистичный сценарий. Допустим, вы хотите построить MCP-сервер, который позволит ИИ-агентам управлять репозиториями GitHub.

**Спросите Claude с активным навыком mcp-builder:**

> "Построй для меня MCP-сервер для GitHub API. Он должен поддерживать создание задач, перечисление репозиториев, управление pull request и поиск по коду."

Claude сделает следующее:
1. Изучит документацию GitHub REST API
2. Спланирует, какие конечные точки покрывать (обычно это 15–25 инструментов)
3. Соберёт полноценный сервер с корректной OAuth-аутентификацией
4. Сгенерирует тестовые оценки для каждого инструмента

В результате вы получите сервер, готовый к продакшену, с корректной обработкой ошибок, пагинацией, ограничением скорости и аутентификацией — то, что при ручной сборке обычно заняло бы несколько дней.

## Ключевые принципы проектирования MCP-серверов

### Покрытие API против инструментов рабочего процесса

Навык mcp-builder помогает удержать важный баланс:

- **Полное покрытие** даёт агентам гибкость в составлении операций
- **Инструменты рабочего процесса** объединяют типичные многошаговые действия в единый вызов
- если есть сомнения, лучше отдавать приоритет полному покрытию API

### Управление контекстом

Агенты лучше всего работают с сфокусированными и релевантными данными:

- возвращайте только те поля, которые действительно нужны агентам, а не весь ответ API
- поддерживайте пагинацию для операций со списками
- добавляйте фильтры, чтобы сужать результаты

### Тестирование и оценка

Навык mcp-builder генерирует автоматические оценки, которые проверяют:

- **счастливый путь** — нормальную работу с валидными входными данными
- **крайние случаи** — пустые результаты, большие наборы данных, специальные символы
- **обработку ошибок** — невалидный ввод, ошибки аутентификации, ограничения по скорости
- **реальные сценарии** — многошаговые рабочие процессы, связывающие несколько инструментов вместе

## Что дальше?

Серверы MCP становятся стандартным способом взаимодействия ИИ-агентов с внешним миром. С навыком mcp-builder вам не нужно быть экспертом по протоколу MCP — Claude берёт на себя сложность, пока вы фокусируетесь на том, что именно должен делать ваш сервер.

Готовы построить свой первый сервер MCP? Вот как начать уже сегодня:

1. **Установите навык**: `npx killer-skills add anthropics/skills/mcp-builder`
2. **Выберите API**: выберите сервис, который хотите интегрировать (Slack, Notion, JIRA и т. д.)
3. **Опишите свои потребности**: расскажите Claude, какие инструменты вам нужны, и он соберёт весь сервер
4. **Разверните и протестируйте**: используйте сгенерированные оценки, чтобы проверить свой сервер

Будущее разработки ИИ — не в том, чтобы писать всё больше кода, а в том, чтобы давать агентам ИИ правильные инструменты для работы. Серверы MCP и навыки агентов делают это будущее возможным уже сегодня.
