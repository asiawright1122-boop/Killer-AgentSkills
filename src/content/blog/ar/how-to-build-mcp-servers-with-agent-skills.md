# كيفية بناء خوادم MCP التي يستخدمها وكلاء الذكاء الاصطناعي فعلاً

ماذا لو كان وكيلك البرمجي المدعوم بالذكاء الاصطناعي يستطيع أكثر من مجرد كتابة الشفرة؟ ماذا لو تمكن من إرسال رسائل Slack، والاستعلام من قواعد البيانات، والنشر إلى الإنتاج، وإدارة خط أنابيب DevOps بالكامل — كل ذلك عبر بروتوكول معياري؟

هذا بالضبط ما تتيحه **خوادم MCP** (Model Context Protocol). ومع مهارة **mcp-builder** الرسمية من مستودع مهارات Anthropic، يمكنك بناء خوادم MCP جاهزة للإنتاج خلال دقائق بدلًا من ساعات.

```bash
# ثبّت مهارة mcp-builder بأمر واحد
npx killer-skills add anthropics/skills/mcp-builder
```

بناء خادم MCP جيد لا يعني اتباع وصفة جاهزة حرفيًا، بل يعني أن تحدد أولًا ما القدرات التي ينبغي كشفها كأدوات، وكيف تصفها بوضوح لكي يفهمها الوكلاء، وما الحدود التشغيلية والأمنية التي يجب وضعها منذ البداية.

## ما هو خادم MCP؟

خادم **MCP** هو خدمة معيارية تعرض أدوات وموارد ومطالبات يمكن لوكلاء الذكاء الاصطناعي استهلاكها. فكّر فيه كجسر بين مساعدك الذكي والعالم الحقيقي — قواعد البيانات، وواجهات البرمجة، وأنظمة الملفات، وخدمات السحابة، وغير ذلك.

أنشأت Anthropic **بروتوكول سياق النموذج** (MCP) لحل مشكلة أساسية: وكلاء الذكاء الاصطناعي يحتاجون إلى طريقة عامة ومتسقة للتفاعل مع الخدمات الخارجية. قبل MCP، كان كل تكامل يتطلب شيفرة مخصصة. أما الآن، فيمكن لبروتوكول واحد أن يتولى ذلك كله.

إليك لماذا يهم MCP:

- **التوافق الشامل** — يعمل مع Claude وCursor وWindsurf وأي عميل متوافق مع MCP
- **واجهة معيارية** — تتبع الأدوات والموارد والمطالبات مخططًا متسقًا
- **تصميم يضع الأمان أولًا** — يتضمن مصادقة مدمجة، والتحقق من الإدخال، وضوابط للأذونات
- **سير عمل قابلة للتركيب** — يمكن للوكلاء ربط أدوات MCP متعددة معًا

## لماذا تستخدم مهارة mcp-builder؟

تُعد **mcp-builder** واحدة من أقوى المهارات في مستودع Anthropic الرسمي. وهي تحوّل Claude إلى مطور متخصص في خوادم MCP عبر توفير ما يلي:

1. **معرفة عميقة بالبروتوكول** — تحمل المهارة مواصفات MCP الكاملة حتى يفهم Claude كل التفاصيل
2. **أفضل الممارسات مهيأة مسبقًا** — تسمية الأدوات، ومعالجة الأخطاء، وأنماط التصفح كلها جاهزة من البداية
3. **دلائل خاصة بالإطار** — قوالب محسنة لكل من TypeScript وPython
4. **توليد التقييم** — تنشئ تلقائيًا مجموعات اختبار لخادم MCP

على عكس البناء من الصفر، تتبع مهارة mcp-builder سير عمل منظمًا في أربع مراحل:

| المرحلة | ماذا يحدث |
|:------|:-------------|
| **المرحلة 1: البحث** | تدرس واجهة البرمجة، وتخطط لتغطية الأدوات، وتصمم مخطط البيانات |
| **المرحلة 2: البناء** | تنفذ الخادم مع معالجة أخطاء صحيحة ومصادقة مناسبة |
| **المرحلة 3: المراجعة** | تختبر جميع الأدوات، وتتحقق من الردود، وتفحص الحالات الطرفية |
| **المرحلة 4: التقييم** | تنشئ تقييمات آلية للتحقق من الجودة |

## كيف تبدأ على أساس عملي

### تثبيت المهارة

لست بحاجة إلى تثبيت CLI تثبيتًا عامًا. أضف مهارة mcp-builder مباشرة عبر `npx`:

```bash
npx killer-skills add anthropics/skills/mcp-builder
```

ستتم إضافة المهارة إلى دليل `.claude/skills/` وتفعيلها تلقائيًا عندما يكتشف Claude مهام تطوير خادم MCP.

### اختيار المكدس

تدعم مهارة mcp-builder مكدسين أساسيين:

**TypeScript (موصى به)**
```bash
npm init -y
npm install @modelcontextprotocol/sdk zod
```

يُنصح باستخدام TypeScript لعدة أسباب:
- دعم SDK عالي الجودة من فريق MCP الرسمي
- يكشف نظام الأنواع عن الأخطاء قبل وقت التشغيل
- توافق قوي مع بيئات التنفيذ
- تمتلك نماذج الذكاء الاصطناعي قدرة جيدة على توليد شيفرة TypeScript

**Python**
```bash
pip install mcp pydantic
```

يُعد Python خيارًا جيدًا إذا كان فريقك يستخدمه بالفعل أو إذا كنت تدمج مع واجهات برمجة تطبيقات كثيفة الاعتماد على Python.

### تعريف أدواتك

مفتاح خادم MCP الرائع هو الأدوات المصممة جيدًا. إليك قالبًا بسيطًا:

```typescript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { z } from "zod";

const server = new McpServer({
  name: "my-api-server",
  version: "1.0.0",
});

server.tool(
  "create_item",
  "ينشئ عنصرًا جديدًا في النظام",
  {
    name: z.string().describe("اسم العنصر الذي سيتم إنشاؤه"),
    description: z.string().optional().describe("وصف اختياري"),
    tags: z.array(z.string()).optional().describe("العلامات للتصنيف"),
  },
  async ({ name, description, tags }) => {
    const result = await api.createItem({ name, description, tags });
    return {
      content: [
        {
          type: "text",
          text: JSON.stringify(result, null, 2),
        },
      ],
    };
  }
);
```

### تطبيق أفضل الممارسات

تفرض مهارة mcp-builder عدة أنماط مهمة:

**اتفاقية تسمية الأداة**
```
github_create_issue
slack_send_message
db_query_users

createIssue
send

```

استخدم بادئات متسقة (اسم الخدمة) مع أفعال موجّهة نحو العمل. هذا يساعد الوكلاء على اكتشاف الأدوات المناسبة واختيارها بسرعة.

**رسائل الخطأ القابلة للتنفيذ**
```typescript
// ❌ سيئة
throw new Error("لم يتم العثور عليه");

// ✅ جيدة
throw new Error(
  `المستودع "${owner}/${repo}" لم يتم العثور عليه. ` +
  `تحقق من وجود المستودع ولديك صلاحية الوصول. ` +
  `حاول سرد مستودعاتك أولاً باستخدام github_list_repos.`
);
```

**تعليقات الأداة**

يجب أن تتضمن كل أداة تعليقات تساعد الوكلاء على فهم سلوكها:

```typescript
server.tool(
  "delete_item",
  "يحذف عنصرًا بشكل دائم",
  { id: z.string() },
  async ({ id }) => { /* ... */ },
  {
    annotations: {
      readOnlyHint: false,
      destructiveHint: true,
      idempotentHint: true,
    }
  }
);
```

## مثال واقعي: بناء خادم MCP على GitHub

دعنا نمر بمثال واقعي. افترض أنك تريد بناء خادم MCP يسمح لوكلاء الذكاء الاصطناعي بإدارة مستودعات GitHub.

**اسأل Claude مع تفعيل مهارة mcp-builder:**

> "ابنِ لي خادم MCP لواجهة GitHub API. يجب أن يدعم إنشاء القضايا، وسرد المستودعات، وإدارة طلبات السحب، والبحث في الشفرة."

سيقوم Claude بما يلي:
1. البحث في وثائق GitHub REST API
2. تخطيط نقاط النهاية التي ينبغي تغطيتها (عادة بين 15 و25 أداة)
3. بناء الخادم الكامل مع مصادقة OAuth مناسبة
4. إنشاء تقييمات اختبار لكل أداة

النتيجة هي خادم جاهز للإنتاج مع معالجة أخطاء مناسبة، ودعم للترقيم الصفحي، وحدود للمعدل، ومصادقة — وهو ما كان سيتطلب عادة أيامًا لبنائه يدويًا.

## مبادئ التصميم الرئيسية لخادم MCP

### تغطية واجهة برمجة التطبيقات مقابل أدوات سير العمل

تعلّم مهارة mcp-builder توازنًا مهمًا:

- **التغطية الشاملة** تمنح الوكلاء مرونة في تركيب العمليات
- **أدوات سير العمل** تجمع العمليات متعددة الخطوات الشائعة في استدعاء واحد
- عند الشك، أعطِ الأولوية للتغطية الشاملة لواجهة برمجة التطبيقات

### إدارة السياق

يعمل الوكلاء بشكل أفضل مع البيانات المركزة والمرتبطة بالسياق:

- أعد فقط الحقول التي يحتاجها الوكلاء، وليس استجابات واجهة البرمجة الكاملة
- ادعم التصفح للعمليات القائمة على القوائم
- أدرج عوامل تصفية لتضييق النتائج

### الاختبار والتقييم

تولّد مهارة mcp-builder تقييمات آلية تختبر:

- **المسار الأساسي** — التشغيل العادي مع المدخلات الصالحة
- **حالات الحافة** — نتائج فارغة، ومجموعات بيانات كبيرة، وأحرف خاصة
- **معالجة الأخطاء** — مدخلات غير صالحة، وفشل المصادقة، وحدود المعدل
- **سيناريوهات العالم الواقعي** — سير العمل متعددة الخطوات التي تربط الأدوات معًا

## ماذا بعد؟

أصبحت خوادم MCP الطريقة القياسية التي يتفاعل بها وكلاء الذكاء الاصطناعي مع العالم. ومع مهارة mcp-builder، لا تحتاج إلى أن تكون خبيرًا ببروتوكول MCP — إذ يتعامل Claude مع التعقيد بينما تركز أنت على ما يجب أن يفعله خادمك.

جاهز للبدء في بناء أول خادم MCP لك؟ إليك كيفية البدء اليوم:

1. **ثبّت المهارة**: `npx killer-skills add anthropics/skills/mcp-builder`
2. **اختر واجهة برمجة التطبيقات**: اختر خدمة تريد دمجها (Slack، Notion، JIRA، إلخ)
3. **صف احتياجاتك**: أخبر Claude بالأدوات التي تحتاجها، وسيبني الخادم بالكامل
4. **انشر واختبر**: استخدم التقييمات التي تم إنشاؤها للتحقق من صحة خادمك

مستقبل تطوير الذكاء الاصطناعي لا يتعلق بكتابة المزيد من الشفرة، بل بإعطاء وكلاء الذكاء الاصطناعي الأدوات الصحيحة للعمل معها. خوادم MCP ومهارات الوكيل تجعل ذلك المستقبل ممكنًا اليوم.
