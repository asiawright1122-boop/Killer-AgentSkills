## Archive Note

This archive preserves the milestone-scoped requirements that were active for `v1.2`, the final traceability mapping used during closeout, and the carry-forward themes identified for the next planning cycle. Fresh active requirements should be defined when the next milestone is started.

## Shipped Requirements

### AI Provider Operations

- [x] **AIOPS-05**: Provider selection can self-tune based on longer-window success rates without hiding operator control or bypassing explicit fallback policy.
- [x] **AIOPS-06**: Provider health history is available in a persistent dashboard or review artifact beyond per-run reports.
- [x] **AIOPS-07**: `src/pages/api/skills/try.ts` and the script-side AI runtime share one common fallback and ranking contract so 429 handling cannot drift by runtime.

### Governance Automation

- [x] **GOV-04**: Content-governance drift can auto-open or auto-seed remediation work when thresholds are crossed.
- [x] **GOV-05**: AI health, content governance, and adjacent smoke or crawl checks run automatically in CI or scheduled monitoring with explicit fail thresholds per context.
- [x] **GOV-06**: Automated operator outputs roll AI health, governance severity, and latest remediation state into one actionable review summary.

### Planning Traceability

- [x] **TRACE-04**: Milestone bootstrap and closeout flows create all planning index files automatically, including milestone registry and historical references used during audit.

## Outcome Notes

- AI operations now share one routing contract across runtime surfaces, longer-window ranking guidance, and explicit Workers free-only guardrails.
- Automated monitoring now publishes AI health, governance, and aggregated ops-summary artifacts without relying on manual shell execution.
- Remediation work is now seedable from structured evidence instead of manual copy-paste.
- Planning traceability now extends into milestone bootstrap and closeout support generation, making audit and archive prep reproducible.

## Carry-Forward Candidates

- **AIOPS-08**: Introduce operator-approved adaptive provider weighting by workload class, not just global history.
- **GOV-07**: Governance remediation seeds can open GitHub issues or PR scaffolds automatically when configured.
- **TRACE-05**: Phase directories can be archived or restored automatically as milestones open and close.
- **UX-EXP-01**: Expand public discovery surfaces only after operator automation is strong enough to keep content and provider drift from silently accumulating.
