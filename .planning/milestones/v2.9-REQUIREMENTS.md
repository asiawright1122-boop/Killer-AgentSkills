# Requirements: v2.9 Coverage Data Ingestion & Post-Intervention Automation

## Overview

Establish automated pipelines for ingesting fresh Google Search Console (GSC) Coverage data to resolve organic reporting freshness SLAs, and implement a telemetry-based post-intervention proof engine that validates directory expansion.

## Scope

### 1. Fresh Coverage Input Ingestion Pipeline (Phase 85)
- **Problem**: GSC coverage data is stale, preventing the verification engine from assessing which URLs are indexed vs excluded.
- **Requirement**: Build a pipeline script `scripts/ingest-coverage-drilldown.ts` that:
  - Validates formatting of GSC Coverage CSV exports.
  - Automatically loads GSC URL indexes into a new database table `gsc_coverage_drilldown`.
  - Marks crawled state of directory roots.
  - Emits alerts when crawled data exceeds the hard 7-day SLA freshness limit.
- **Verification**: Ingestion of a sample GSC CSV successfully updates `gsc_coverage_drilldown` table with zero database syntax errors.

### 2. Post-Intervention Proof Engine (Phase 86)
- **Problem**: We need data-driven proof of search recovery to justify unlocking directory expansion.
- **Requirement**: Implement a cross-referencing logic script `scripts/verify-recovery-proof.ts` that:
  - Cross-references the `gsc_coverage_drilldown` records with our current `skills` database.
  - Calculates technical recovery metrics (indexed ratio, canonical alignment, 404 remediation efficacy).
  - Generates a markdown scorecard in `.planning/dashboards/recovery-scorecard.md`.
- **Verification**: The script evaluates sample data and successfully outputs the scorecard with accurate metrics.

### 3. Automation Policy Unlock System (Phase 87)
- **Problem**: The directory expansion automation policy is currently locked by default.
- **Requirement**: Modify the directory expansion gates to:
  - Dynamically read the `.planning/dashboards/recovery-scorecard.md` or DB indicators.
  - Automatically unlock the directory expansion policy if technical recovery threshold >= 95% and business recovery metric is healthy.
- **Verification**: Test dry-runs of the promotion engine with mock healthy metrics unlock the directory expansion policy, while poor metrics keep it locked.
