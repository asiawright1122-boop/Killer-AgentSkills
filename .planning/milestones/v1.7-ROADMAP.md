## Overview

This milestone treated internal strategy/process leakage on public pages as a product-trust problem rather than a one-off copy bug. The shipped result audited the main public entry surfaces, normalized the highest-impact templates and shared content sources, and added reusable guardrails so known internal/operator wording families are blocked before release.

## Milestone Summary

### Key Accomplishments

1. Confirmed the leak family across public page shells, shared collection JSON, locale catalogs, and authority-surface helper data instead of treating the homepage symptom as isolated.
2. Normalized the main public entry surfaces so they now read like product guidance rather than operator process notes.
3. Removed repeated internal-language families from shared public sources at the source instead of only patching rendered templates.
4. Upgraded `tests/pages/public-links.test.ts` into a directory-level trust-surface guardrail that scans pages, shared data, locale catalogs, and collection JSON together.
5. Closed the milestone with `3/3` requirements satisfied, `3/3` phases complete, and a passed milestone audit.

### Key Decisions

- Treat public/internal language leakage as a trust-surface milestone, not a one-off copy bug.
- Fix shared public sources at the source instead of only rewriting rendered templates.
- Keep the guardrail phrase-family based and scope-based for low-noise CI enforcement.
- Leave internal/operator planning artifacts untouched; only shipped public surfaces belong in the copy-boundary contract.

### Issues Resolved

- Public entry pages no longer present operator-style strategy/process guidance on the main audited surfaces.
- Shared collection JSON, locale catalogs, and authority-surface helper data no longer re-seed the removed wording families into public templates.
- Regression coverage no longer depends on a small representative-file sample.

### Deferred / Watchlist

- The current guardrail is intentionally phrase-family based, so future semantic variants still need manual rule-set expansion.
- Broader recovery-proof blockers remain the next milestone's problem; `v1.7` intentionally did not reopen authority expansion or automation.
- Fresh Coverage Drilldown inputs and a second trustworthy post-governance proof window are still required before growth decisions can change.
