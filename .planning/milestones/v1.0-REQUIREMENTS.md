The original `.planning/REQUIREMENTS.md` for `v1.0` became stale relative to the roadmap as the milestone evolved. This archive preserves both:

## Original Snapshot

### Must Haves

- Instantiate `.planning/` directory logic with deep codebase inspection.
- Enforce strict separation between CI workflows and local test injections (`ADMIN_USER`, `ADMIN_PASSWORD`).
- Ensure all 11 steps of `.github/workflows/ci.yml` strictly pass unattended.
- Refactor legacy references mapped in unit tests to match extracted Astro components (for example `SkillRelated`).

### Nice to Haves

- Fully auto-generated SEO reports pushed systematically onto GitHub cache releases.

### Anti-Requirements

- Do not migrate away from Astro SSR or Cloudflare D1.

## Outcome Notes

- The original requirement about CI drift and extracted component assertions was fully addressed by Phases `01` and `02A`.
- The original requirement to instantiate `.planning/` with deep codebase inspection expanded into a full GSD-managed milestone with summaries, verifications, audit artifacts, and milestone closeout structure.
- The original requirement set did not explicitly model the SEO regeneration/publish/audit work that became central to the milestone. Those requirements were captured in the roadmap and are now the authoritative execution record for `v1.0`.
- The Astro SSR + Cloudflare D1/KV architecture remained intact throughout the milestone and remains an explicit anti-requirement guardrail.

## Carry-Forward Debt

- Future milestone requirements should be traceability-rich and machine-readable from the start.
- Requirement completion should be reflected both in roadmap metadata and summary frontmatter so milestone audits are less manual.
- Provider reliability hardening and translation/content governance should be expressed as explicit next-milestone requirements rather than informal watchlist items.
