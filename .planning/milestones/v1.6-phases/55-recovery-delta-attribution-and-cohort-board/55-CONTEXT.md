# Phase 55: recovery-delta-attribution-and-cohort-board - Context

**Gathered:** 2026-04-16
**Status:** Ready for planning
**Source:** `v1.6` roadmap, `v1.5` baseline archive, Phase `54` proof-window goals, and the need to separate real recovery from noise

<domain>
## Phase Boundary

This phase turns dated proof windows into interpretable movement by cohort.

This phase covers:

- comparing fresh proof windows against the archived `v1.5` baseline
- attributing movement by authority-surface group, locale, page cohort, and issue cluster
- separating `real movement`, `measurement lag`, and `still blocked` states in one board
- making sure post-governance recovery decisions are based on comparable evidence instead of intuition

This phase does not cover:

- editorial uplift execution itself
- broad authority-surface expansion
- experiment automation or rollout ladders
</domain>

<decisions>
## Implementation Decisions

- **D-01:** Delta views should anchor to the archived `v1.5` end-state and the dated proof windows from Phase `54`.
- **D-02:** Authority-surface grouping must sit beside locale and cluster attribution, not outside it.
- **D-03:** A delta board should expose confidence and freshness, not only directional arrows.
- **D-04:** This phase should produce attribution that Phase `56` can act on without re-interpreting raw reports manually.
</decisions>

<specifics>
## Specific Ideas

- `v1.5` established structural governance, but we still do not know which cohorts are improving versus merely less noisy.
- Authority surfaces, governed skill canonicals, and suppressed long-tail cohorts should probably be compared side by side.
- The board should help answer whether wins are coming from homepage / collections / docs / workflow surfaces or from the governed directory itself.
</specifics>
