# Phase 01.1: Stabilize frontend interactions, breadcrumbs, i18n, and SEO contracts - Context

**Gathered:** 2026-03-30
**Status:** Ready for planning
**Source:** PRD express path from repo audit and live-site verification

<domain>
## Phase Boundary

This phase fixes urgent public-surface breakage in the Astro frontend shell and its shared page contracts.

The phase covers:
- Clickability and interaction reliability on public pages
- Shared card/link interaction behavior
- Public i18n fallback correctness
- Breadcrumb UI plus breadcrumb structured-data consistency
- Shared canonical and hreflang behavior for touched page types
- Locale source-of-truth alignment across runtime app code, scripts, and workers
- Local dev/build reproducibility for this surface area
- Regression coverage for interaction, i18n leakage, and metadata consistency

This phase does not cover full SEO content regeneration or broader growth work.
</domain>

<decisions>
## Implementation Decisions

### Frontend interaction reliability
- Treat user-reported "pages almost unclickable" as a top-priority production bug.
- Remove or normalize page-local stretched-link, z-index, and pointer-events hacks where they create inconsistent interaction layers.
- Ensure closed overlays and decorative layers never intercept pointer events.
- Add click-through verification for critical user journeys; DOM-presence checks alone are insufficient.

### i18n contract
- Raw translation keys must never render on public pages.
- Replace implicit `t('...') || fallback` assumptions with an explicit helper or contract that distinguishes "missing translation" from "translated string".
- Centralize locale definitions so runtime app code, scripts, and workers do not drift.

### Breadcrumb and SEO contract
- Breadcrumb UI and breadcrumb JSON-LD must derive from one shared model.
- Canonical and hreflang generation should use shared builders/helpers for touched page types.
- Visible locale, metadata locale, and served content should remain aligned on target pages.

### Delivery and verification
- Restore `npm run dev` before claiming the phase is complete.
- Add regression tests for interaction, i18n key leakage, and shared metadata/breadcrumb behavior.
- Include a smoke check path for repo/live drift on the touched pages.

### the agent's Discretion
- Exact helper names and file boundaries
- Whether shared builders live in `src/lib`, `src/components`, or a new shared contract module
- Whether interaction primitives are extracted as Astro components or utility helpers
</decisions>

<specifics>
## Specific Ideas

- Normalize the click model for cards so the same primitive is used by skills and collections.
- Audit overlay state after Astro transitions and mobile menu close.
- Introduce a translation helper such as `translateOr`, `hasTranslation`, or equivalent.
- Add a test that scans public-page translation usages and fails on missing keys.
- Build a shared breadcrumb/meta input shape that can power both UI and JSON-LD.
- Add smoke assertions for `/en`, `/zh`, `/en/skills`, `/en/collections`, and one skill detail page.
</specifics>
