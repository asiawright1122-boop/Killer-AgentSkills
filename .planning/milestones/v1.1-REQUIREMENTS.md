## Archive Note

This archive preserves the milestone-scoped requirements that were active for `v1.1`, the final traceability mapping used during closeout, and the carry-forward themes identified for the next planning cycle. Fresh active requirements should be defined when the next milestone is started.

## Shipped Requirements

### AI Provider Operations

- [x] **AIOPS-01**: Operator can generate one health summary that shows provider availability, cooldowns, quarantines, strongest NVIDIA labels, and current alert severity.
- [x] **AIOPS-02**: Batch and report flows stop, downgrade, or flag explicitly when provider health crosses configured warning or blocking thresholds.
- [x] **AIOPS-03**: Workers AI usage remains provably constrained to free-only run and daily limits with audit evidence attached to each relevant run.
- [x] **AIOPS-04**: Backup providers only activate under explicit guarded conditions, and each activation is recorded with reason in telemetry outputs.

### Planning Traceability

- [x] **TRACE-01**: Each phase summary records machine-readable completed requirement IDs.
- [x] **TRACE-02**: Milestone audits can determine requirement coverage from `REQUIREMENTS.md`, phase summaries, and verification artifacts without manual reconstruction.
- [x] **TRACE-03**: Planning directory hygiene prevents archived or orphaned phase artifacts from distorting phase discovery and completion status.

### Content Governance

- [x] **GOV-01**: Operator can run one governance command that surfaces locale/content drift before a broad regeneration queue accumulates.
- [x] **GOV-02**: Representative localized public routes fail verification when translation, breadcrumb, metadata, or tutorial-shell drift reappears.
- [x] **GOV-03**: Governance outputs distinguish warning-only debt from publish-blocking failures in machine-readable form.

## Outcome Notes

- Provider health, fallback posture, and Workers AI free-tier evidence now share one operator-facing contract instead of living in fragmented scripts and workflows.
- The planning lane now exposes machine-readable requirement coverage so milestone closeout and future audits can compute scope completion directly from repository artifacts.
- Locale/content governance moved from scattered checks to one explicit `clear / warning / blocking` report lane.
- `v1.1` closed with `10/10` requirements satisfied, `4/4` roadmap phases complete, and no blocking audit gaps.

## Carry-Forward Candidates

- **AIOPS-05**: Provider selection can self-tune based on longer-window success rates without hiding operator control.
- **AIOPS-06**: Provider health history is available in a persistent dashboard or review artifact beyond per-run reports.
- **GOV-04**: Content-governance drift can auto-open or auto-seed remediation work when thresholds are crossed.
- **TRACE-04**: Milestone bootstrap and closeout flows create all planning index files automatically, including milestone registry/history.
