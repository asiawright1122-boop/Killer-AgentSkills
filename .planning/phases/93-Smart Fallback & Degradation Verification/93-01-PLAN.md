# Plan: Phase 93 (Smart Fallback & Degradation Verification)

## Core Tasks

### 1. 模拟 429 与 Cooldown 降级测试
- **目标**: 验证 NVIDIA 报错限流时，流量正确退回到健康的备份 Provider。
- **Action**:
  - 在 `src/lib/ai-provider-routing.test.ts` 中增加测试用例。
  - 构造 `stateByLabel`，将主 Provider（如 `N0`）的 `consecutive429s` 设为大于 0 的数，且将 `coolingDown` 设为 `true`。
  - 调用 `buildProviderRoutingPlan`，传入 `policy: 'guarded'`。
  - 断言 `plan.primaryOrder` 为空，`plan.backupOrder` 包含健康的备份 Provider。
  - 断言决策 `plan.fallbackRouting.decision` 正确为 `backup_recovery`。

### 2. 模拟密钥丢失与未配置退回测试
- **目标**: 验证主 Provider 未配置或彻底不可用时的路由降级反应。
- **Action**:
  - 增加测试用例，将 `nvidiaConfigured` 设为 `false`，或者 `primaryCandidates` 的 `available` 设为 `false`。
  - 断言在 `policy: 'guarded'` 下备份能够自动允许（`backupsAllowed: true`），且正确转向备份 Provider。
  - 断言在 `policy: 'cold'` 且主 Provider 不可用时，由于 `backupsAllowed: false`，决策正确指向 `backup_policy_blocked` 或 `providers_exhausted`。

### 3. 未声明/熔断的 Provider 锁定退回路径测试
- **目标**: 验证熔断或硬禁用的备份 Provider 绝对不会被作为路由候选，且当所有 Provider 耗尽时返回 `providers_exhausted`。
- **Action**:
  - 构造包含多个备份候选者（如 `siliconflow`, `openrouter`, `cloudflare`）的 `backupCandidates`。
  - 在 `stateByLabel` 中将其中一部分备份设为 `hardDisabled: true` 或 `circuitBreakerOpen: true`。
  - 验证 `plan.backupOrder` 中不含这些熔断/禁用的 Provider。
  - 将所有 Primary 和 Backup 的候选者状态都在 `stateByLabel` 中设为熔断或不可用。
  - 调用 `buildProviderRoutingPlan` 并断言决策 `plan.fallbackRouting.decision` 为 `providers_exhausted`。

### 4. 预算（budget）与速度（speed）Profile 排序算法验证
- **目标**: 验证当操作员 Profile 设为 `budget` 或 `speed` 时，候选者能依据成本或延迟降序/升序正确排列。
- **Action**:
  - 构造备份候选者，在 `stateByLabel` 中为它们赋予不同的 `estimatedCostPer1k` 和 `averageLatencyMs`。
  - 传入 `operatorProfile: 'budget'`，断言 `backupOrder` 按 `estimatedCostPer1k` 从低到高排序。
  - 传入 `operatorProfile: 'speed'`，断言 `backupOrder` 按 `averageLatencyMs` 从低到高排序。
