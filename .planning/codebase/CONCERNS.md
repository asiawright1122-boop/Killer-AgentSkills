# Concerns: SEO, Crawling, Theme Drift & Data Quality

## 1. SEO Architecture

### Current Implementation
- Per-skill SEO data stored inline: `seo.definition`, `seo.features`, `seo.keywords` — all as `Record<locale, string/string[]>`
- `seo.title` and `seo.description` per locale generated by AI during `build-skills-cache.ts`
- Sitemap generated from D1/KV via `getSitemapSkillsFromKV()` with a 5-minute in-memory cache (`SITEMAP_SKILLS_CACHE_TTL_MS`)
- i18n routing: all 10 locales get full URL prefixes (`/en/`, `/zh/`, etc.)
- Blog content exists in 10 locales under `src/content/blog/[locale]/`
- Scripts: `submit-indexnow.mjs`, `submit-baidu.mjs`, Google submit for index notification
- SEO audit scripts: `seo-report.ts`, `seo-generate-keywords.ts`, etc.

### Strengths
- AI-generated per-locale SEO metadata (title, description, keywords, definition) for every skill
- Full 10-locale coverage for discovery in non-English markets
- IndexNow + Baidu submission scripts for fast indexing
- Structured sitemap from live data

### Gaps & Risks
- No structured data (JSON-LD / schema.org) found in core components — missed rich snippet opportunity
- SEO metadata quality depends entirely on AI generation quality — no human review gate
- Sitemap TTL is 5 min in-memory only; no persistent sitemap.xml caching layer observed
- `seo.title`/`seo.description` are optional fields on `UnifiedSkill` — missing for older entries
- No canonical tag enforcement strategy documented
- No Core Web Vitals monitoring observed

## 2. Crawling / Data Ingestion Pipeline

### How Data Enters
1. **GitHub Crawler** (`scripts/harvest-github-skills.ts`) — searches GitHub for repos containing `SKILL.md` files via GitHub Search API
2. **Manual submission** — `/api/crawled-skills/index.ts` accepts POST submissions; stored pending review
3. **Admin API** (`/api/admin/skills.ts`) — direct admin write path

### Validation at Ingestion
- `EXCLUDE_KEYWORDS` list checked against repo name/description (25 terms: interview, resume, leetcode, etc.)
- `NON_TARGET_THEME_PATTERNS` regex array (4 patterns: interview, career-prep, product-management, mvp-startup)
- `SUSPICIOUS_NAMES` list (test, demo, example, hello-world, todo, temp, dummy)
- `SKILL_HEADERS` check — looks for structural headers (`# Usage`, `## Input`, etc.) to confirm it's a real skill
- Quality scoring (`qualityScore`) considers: source tier (verified/featured/cache), description length, recency, stars

### Pipeline Orchestration
- `run-pipeline.sh`: harvest → build → KV sync (daemon or `--once` mode)
- `run-full-automation.sh`: extended automation including D1 delta sync
- Runs on VPS via PM2 or cron

## 3. Data Generation & Storage

### Key Schema Fields (SkillListingItem / UnifiedSkill)
- `id`, `owner`, `repo`, `name`, `skillName`, `description` (localized), `category`, `topics`, `stars`, `forks`
- `source`: `verified` | `featured` | `cache` (tiered trust)
- `qualityScore`: float 0–1, composite of source tier + description richness + recency + stars
- `seo`: AI-generated `{ definition, features, keywords }` per locale
- `agentAnalysis`: AI-generated `{ suitability, recommendation, useCases, limitations }` per locale
- `skillMd`: raw SKILL.md content `{ name, description, version, tags, body, bodyPreview }`
- `lastSynced`, `updatedAt`

### AI Enrichment
- Providers: NVIDIA NIM API (primary), SiliconFlow (fallback), OpenRouter (fallback)
- Multiple API keys with round-robin rotation (`currentNvidiaKeyIndex`)
- Translation languages: zh, ja, ko, de, es, fr, pt, ru, ar (9 non-English)
- Doc translation: `build-docs-cache.ts` translates documentation pages to all 9 locales

### Storage Write Path
- KV (`SKILLS_CACHE`): individual skill blobs by `owner/repo` key + listing cache
- D1: FTS5-indexed table for full-text search; delta syncs only changed rows

## 5. Theme Drift Analysis (CRITICAL)

### What "On-Theme" Means
The platform indexes **Claude Agent Skills** — repos containing `SKILL.md` files designed to be used with Claude Code or similar AI agents.

### Current Filtering Mechanisms

#### Hard Exclusions (`EXCLUDE_KEYWORDS` — 14 terms)
- interview, notes, blog, resume, portfolio, leetcode, algorithm, tutorial, course, book, learning, study, guide, product manager, product management, mvp builder, mvp-generator
- Applied against: repo name, description, topics

#### Regex Theme Patterns (`NON_TARGET_THEME_PATTERNS` — 4 patterns)
- `interview/mock interview/interview prep` → reason: `interview`
- `resume/portfolio/leetcode` → reason: `career-prep`
- `product manager/pm-os/prd-writer/jobs-to-be-done` → reason: `product-management`
- `mvp builder/startup pitch` → reason: `mvp-startup`

#### Structural Validation
- `SKILL_HEADERS` presence check ensures SKILL.md has proper sections
- `bodyPreview` minimum length implied (≥220 chars in tests for indexable content)
- `SUSPICIOUS_NAMES` catch test/placeholder repos

### Weaknesses
- **Narrow exclusion list**: Only 4 regex patterns and ~14 keyword terms. Many off-topic repos with SKILL.md could pass (general productivity tools, non-AI tools, etc.)
- **No positive theme assertion**: Filtering is purely negative (exclusion) — there's no check that a skill is *actually* AI-agent-oriented
- **GitHub topic gaming**: A repo could add misleading topics to pass filters
- **No human review gate**: All filtering is automated; no manual curation step
- **No re-validation on update**: Once indexed, skills are not re-validated against current exclusion rules unless re-crawled
- **Category drift**: `category-taxonomy.ts` normalizes categories but doesn't enforce AI-relevance

### Recommendations
- Add positive keyword list (must contain at least one: `claude`, `cursor`, `ai agent`, `mcp`, `llm`, `prompt`, etc.)
- Add confidence scoring to `getNonTargetSkillReason` and threshold-gate indexing
- Implement periodic re-validation sweep against updated exclusion rules
- Consider lightweight human spot-check queue for borderline quality scores

## 6. Natural Traffic Optimization

### Current Keyword Strategy
- AI generates `seo.keywords` per skill per locale during build
- No observed keyword research process feeding into generation prompts
- `scripts/seo-generate-keywords.ts` exists — purpose unclear without reading

### Ranking Signals Used
- `qualityScore`: source tier + description length + recency + log(stars)
- Fuse.js search weights: `skillName`, `name`, `description`, SEO keywords/definition/features
- D1 FTS5: BM25-style ranking via SQLite FTS5

### Missing Opportunities
- No internal linking strategy documented
- No page-level keyword density controls
- Collections and Solutions pages exist but SEO optimization unclear
- No schema.org `SoftwareApplication` or `HowTo` markup for rich results
- No search intent categorization (navigational vs. informational vs. transactional)
- `skill-try` lab page (AI playground) not surfaced in main navigation per routing analysis
