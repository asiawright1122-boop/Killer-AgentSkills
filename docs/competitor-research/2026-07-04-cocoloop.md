# 竞品研究报告 — CocoLoop vs Killer-Skills

**研究类型：** 内容 + SEO 定位 + 产品入口面
**日期：** 2026-07-04
**竞品域名：** `hub.cocoloop.cn`
**我方域名：** `killer-skills.com`
**作者：** Killer-Skills SEO 工作组
**状态：** 现场验证完成(竞品首页、`/safe`、`/skills`、一个 skill 详情页、`sitemap.xml`;我方 `sitemap-skills.xml`、`authority-surfaces.json`、live 首页)

---

## 执行摘要

CocoLoop 比我们晚做,却为**中文用户**搭了一个更锋利、更有说服力的产品入口面。他们赢的不是规模、i18n、搜索或工程严谨度——那些都是我们的。他们赢在**三件杠杆率极高的小事**:

1. **一页信任页(`/safe`)**——定位为"恶意 Skill 专杀工具",把"装 Skill 会不会偷我 API key / 跑 rm -rf"这个用户最大的恐惧点变成自己的护城河。
2. **一句记得住的价值主张**——`更快更安全的 AI Agent Skills 商店`(10 个汉字)vs 我们的 `Install 3,400+ AI Agent Skills & MCP Servers`(66 个英文字符、4 个概念)。
3. **首页策展化的榜单 + 专题**——榜单排名和专题直接在首页成为一个清晰入口,而不是扁平目录列表。

**3 条最高优先级建议**(完整优先级表见文末):

1. 起一个 `/safe`(以及 `[locale]/safe`)authority surface 页——不去模仿 CocoLoop,而是**用工程化反超**:把我们已有的 ESLint hard gate、`SKILL.md` schema 校验、`killer-skills-ignore` opt-out topic、`.github/TAKEDOWN-POLICY.md` 当作信任资产摆出来,这些是他们无法仿造的硬事实。这一页我们应该自己拥有,因为我们其实就是真正在跑这些 enforcement。
2. 把首页 H1 / hero 改成**两形容词 + 一名词**的每语言版本(英文:"Verified. Secure. AI Agent Skills." 中文:"已验证 · 更安全 · AI Agent 技能目录"),把 `3,400+` 这种规模数字下沉到副标题。1 行 copy 改动,召回率上行空间却很大。
3. 把 skill 详情页 H2 模板对齐 CocoLoop 的六维模板(`核心用法 / 显著优点 / 潜在缺点 / 适合的目标群体 / 使用风险 / 相关 Skills`)。我们已有的 `audit:seo:index-quality` hard gate 已经在管薄内容;再加一条 H2 覆盖规则,就能让 1,649 个 live skill URL 收敛到同一个编辑模板上,而不是各行其是。

### 为什么他们的入口面这么锐
- `<title>` 堆关键词(`Skill商店_OpenClaw Skill技能下载_CocoLoop更安全的Skill市场`)——这是老派中文 SEO 做法。
- H1 **反堆关键词**:它对人讲(`更快更安全`),不是给爬虫讲。这个分工其实很讲究——title 扛长尾关键词,H1 扛用户召回。
- "快速安装"这个 H2 加上"或者通过你的 Agent 添加"这个 H3,是**双安装路径**(CLI / Agent),正好是我们的战场——但他们把它做在 skill 页里,不是单独 SDK 文档。

### 诚实的判断
我们的语料**大他们 3–10 倍**,i18n **多 10 倍**,API surface 完全不在一个量级,SEO 治理工具链也实质更成熟。CocoLoop 的领先**不是规模或技术——是形状**:一页信任页、一句扁平口号、首页编辑式策展。这些都是**非常便宜就能追上的东西**,所以这个 gap 反而最尴尬。

## 7. 方法与验证

**竞品(2026-07-04 现场验证):**
- 首页(`https://hub.cocoloop.cn/`)——title、H1–H3、meta、nav、hero、榜单
- `/safe`——完整信任内容页(六维检测 + 对照表)
- `/skills`(列表)
- 一个 skill 详情页(`/skills/1430`)——H2 模板、`SoftwareApplication` + `BreadcrumbList` JSON-LD
- `sitemap.xml`——6 条 URL 的扁平 urlset(`/`、`/search`、`/article`、`/cls`、`/safe`、……)

**我方(live 验证):**
- `https://killer-skills.com/en`——title、H1(`Verified AI Agent Skills Secure Directory`)、meta description
- `https://killer-skills.com/sitemap-skills.xml`——live 抓取 **1,649** 条 `<loc>`
- `data/authority-surfaces.json`——44 个 P0 surface + editorial queue
- `data/sitemap-skills.json`——内部 dataset 中 2,664 条 skill URL(live sitemap 已 вышел 1,649)
- README / `scripts/seo-authority-*` / CI `audit:seo:index-*` hard gate

**未验证(需跟踪):**
- 本次会话**没能 fetch 到任何一个 live 的 Killer-Skills skill 详情页**——两个测试 URL(`/en/obra/superpowers`、`/en/chandima/opencode-config/github-ops`)返回 404,一条合法 sitemap URL 返回空 body(疑似限流或瞬时)。本报告里所有关于我方 skill 详情页 H2 / JSON-LD 覆盖的论断,都是**从模板代码和 CI gate 推断**,不是 live 确认。在 R3 / R4 声称"对齐"或"gap"之前,应抽样一个 live URL 复验。

**边界:**
- 本报告只用公开、无需认证的抓取。没有抓登录后内容。
- CocoLoop 有姊妹 App(社区 / 直聘 / 生图 / Molili);本报告**有意不评估它们**,因为它们不是本次要评估的 SEO 竞品面。

## 8. 一段式结论

他们做得"好"不是因为比我们强,而是因为我们已经有护城河(ESLint hard gate / SKILL.md schema / `killer-skills-ignore` / take-down policy / 1,649 URL 语料 / 10 locale / Vectorize / CLI / 公开 API)却没有把它做成**一页让用户看到的故事**。CocoLoop 把"安全 + 策展 + 单一价值主张"三件事拍成了首页和 `/safe`,我们把这些资产藏在 CI 和 README 里。最值得做的不是去模仿他们扁平的中文站点或龙虾 IP,而是把 `/safe` 做成可入库的 P0 authority surface、把首页 H1 拍扁成两形容词一名词、用 `audit:seo:index-quality` 现有的 gate 把 1,649 个 skill 详情页收敛到统一的六维 H2 模板。这三步对应优先级最高的 R1 / R2 / R3。
